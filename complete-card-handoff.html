Import Card

Shipped as .import-card in @taxhawk-swoop/common v3.5.0 (was: Complete Card). Source: Shoebox v11 income upload mock. Colton Bragg (UX) · 2026-08-05, updated 2026-08-14 · Handoff for @taxhawk-swoop/common.

Purpose

One card per uploaded document on the upload page, covering the file’s whole lifecycle: loading (upload in progress), ready to import (confirm the detected form type or remove the file), uncategorized (warning treatment with an explanation block), and failed (error treatment). Desktop layout plus a stacked mobile layout below 576px.

Instances

All shipped states, rendered with the real compiled CSS linked above — these are live, not mockups. The badge on every card is the actual form-type <select>; try switching one to Uncategorized. The remove button works too.

Mobile preview

Mobile layout rules (375px) — confirmed against the original spec, with one fix made during build:

  • Icon, filename block, and the remove button top-align — not vertically centered. (The first build pass centered the remove button against the full row height at every size; fixed to align to the top below the sm breakpoint.)
  • The form-type badge drops to a second line, aligned with the text column, not under the icon.
  • Filename wraps to a maximum of two lines, then truncates with an ellipsis — applies at all breakpoints.

Anatomy

PartSpec
File-type iconOfficial set (32×40, Figma node 4605-20616 — download as provided; static multi-color SVGs, not mask icons), one per card, leading. The failed variant hides it and shows a 24px alerts-feedback/alert-octagon.svg in $svg-danger instead.
FilenameText md/Medium, $text-default (failed: $text-subtle). Max two lines, then ellipsis — all breakpoints.
Status lineText sm/Regular, $text-help (failed: $text-subtle). Copy per state: “Ready for import” / “Failed to process file”.
Form-type badgePackage badge (badge-style(primary); warning in the uncategorized variant) over a native <select> with a width-sync select.width-temp-select twin. Hidden in the failed and loading variants.
Retry badgeFailed only — danger badge with refresh icon in the form-type badge’s grid slot. Styled and in the markup, but not wired to a retry action yet (planned).
Remove button.btn.btn-icon, 40×40, 24px x icon, aria-label="Remove <filename>". Hover: variant surface tint + mix-blend-mode: multiply. Hidden while loading.
Warning blockUncategorized only: .alert.warning-message with alert-triangle ($svg-warning), “Uncategorized Document” title, body with My Tax Files link (consumer sets the href). aria-live="polite".
Progress overlay.card-progress — brand-tinted bar behind the content; width driven by JS during upload.

Behavior

  1. The badge opens a native <select> with the full SWOOP form-type list; the label updates immediately (width synced via the package’s dropdown listener).
  2. Selecting Uncategorized toggles the .uncategorized class on the root via the package’s index.js listener, revealing the warning block; selecting a real form type reverts it. Live in the examples above.
  3. Remove deletes the card, no confirmation (recoverable by re-uploading).
  4. A failed card has no classification control; the retry badge sits in its place but is not wired yet — today recovery is remove and re-upload.
  5. Every card renders the full markup up front; the .uncategorized / .failed / .loading classes on the root show and hide the parts. No wrappers, no per-element JS.

Accessibility

  • The badge remains a real <select>; focus styling comes from the package badge’s :focus-within states.
  • The warning block carries aria-live="polite" aria-atomic="false".
  • Remove button: aria-label="Remove <filename>". All icons aria-hidden="true".
  • Text/surface pairs meet 4.5:1 contrast.

Build Notes

  • Shipped in @taxhawk-swoop/common v3.5.0: src/scss/components/_import_card.scss, markup in test/index.html, listeners in src/scripts/index.js.
  • Three FIXME primitives remain in the shipped SCSS: the uncategorized/failed card surfaces ($warning-25 / $danger-25 — new $surface-warning-light / $surface-danger-light tokens approved 2026-08-14) and the warning divider ($warning-100 — resolved to reuse $border-warning).
  • Consumers import the package SCSS and index.js; the jQuery listeners at the bottom of this page are the package’s own, reproduced so the examples are live.

Do / Don’t

DoOne card per uploaded file, stacked oldest-first (the component adds the 8px gap between cards).
Don’tAdd extra action buttons, remove parts from the markup (variant classes rely on the full structure), or use outside an upload list.

Open Questions

  • Retry badge: wire it to a real retry action, or drop it until the upload-flow rewrite lands? (Earlier UX direction removed retry; the shipped version styles it as planned.)
  • Token follow-ups approved 2026-08-14: add $surface-warning-light / $surface-danger-light and switch the divider to $border-warning — swap out the three FIXMEs when they land.
