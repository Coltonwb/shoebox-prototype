Complete Card

Working name — final class/tag name TBD with dev. Source design: Shoebox v11 income upload (ready-for-import state). Prepared by Colton Bragg (UX) · 2026-08-05 · Draft for dev handoff into @taxhawk-swoop/common.

Purpose

The Complete Card represents one uploaded document that finished uploading and is ready to import. It confirms what the file is (name + detected form type), lets the user correct the classification in place, and lets them remove the file — without leaving the upload page.

Instances

All shipped permutations. The badge on every card is the live form-type selector; switching any card to Uncategorized converts it to the warning variant below.

Default — one card per file type icon (PDF, JPG, PNG, xlsx), various detected form types, including a long-filename case.

Mobile layout rules (375px):

  • Icon, filename block, and the remove button’s clickable area top-align — not vertically centered.
  • The form-type badge drops to a second line, aligned with the text column (not under the icon).
  • Filename wraps to a maximum of two lines, then truncates with an ellipsis (applies at all breakpoints).

Palette drift found during handoff: the current mockup renders the warning icon in #f79009, which is not a SWOOP primitive. Build with $warning-500 (or UX picks another token) — do not carry the hex forward.

Behavior

  1. The badge opens a native form-type <select> (full SWOOP form-type list). Changing the value updates the badge label immediately.
  2. Selecting Uncategorized converts the card to the warning variant and appends the warning block; selecting any real form type converts it back. The transition happens in place.
  3. The remove button deletes the card from the list. No confirmation (recoverable by re-uploading).
  4. The card itself is not clickable; only the badge and remove button are interactive.

Accessibility constraints

  • The badge must remain a real <select>; focus shows the SWOOP ring (0 0 0 4px $brand-100; warning variant $warning-100).
  • The warning block appears after user interaction → aria-live="polite" aria-atomic="false".
  • Remove button: aria-label="Remove <filename>". Icons decorative → <span data-th-icon aria-hidden="true">.
  • Badge text/surface pairs above meet 4.5:1; keep any new pairs at or above that.

Build constraints

  • Ship in @taxhawk-swoop/common: one SCSS component + docs page in /.claude/docs/components/, following package conventions (single base class + variant modifier, like .audit-message).
  • Tokens only — every value above maps to an existing token; no raw hex, no scoped overrides of other components.
  • Icons from the SWOOP file-type set via the mask-image pattern in /docs/icons.md.
  • Any JS (badge label sync, variant toggle) belongs in the package’s index.js DOM initialization.
  • Class names in these examples are mockup working names — dev + UX agree final naming before build.

Do / Don’t

DoOne card per uploaded file, stacked oldest-first, 8px gap. “Ready for import” is the only status this component shows.
Don’tReuse for in-progress or failed uploads, add extra action buttons, or place outside an upload list.
